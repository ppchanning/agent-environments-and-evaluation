## 1. GlobeBench: Evaluating Text-Based World Model Capabilities for Scalable Environment Simulations

Patronus AI；Nicholas Saban、Charvi Bannur、Mariya Vasileva、Darshan Deshpande；2026-10-15 v1，预印本，近30天补读。[原文与PDF](https://arxiv.org/abs/2610.22708) · [作者介绍](https://www.patronus.ai/research/globebench)

作者问的不是智能体会不会选工具，而是充当环境的模型能否正确回答一次动作。在文本仿真里，一条回复读起来合理，不代表它记住了很早以前的写入，也不代表修改已经传到所有依赖对象。论文把这种笼统的“像不像环境”拆成19种可单独检查的行为，例如读写持久性、引用完整性、部分失败和错误拒绝。

每道题给模型此前可见的动作与环境回复，再给最后一个动作，要求预测接下来的状态或响应。正确参考来自固定软件后端执行，不让被测模型看见。作者通过动作骨架安排关键写入、读取、删除或权限变化，并插入不影响目标状态的动作，改变模型要回溯多远；另一维度是动作影响多少相关对象。论文图1用图书数据库解释：修改书名以后搜索应显示新名，无效会员借书应报错且不改状态。这些是论文的说明示例，不是我们新做的实验。

数据共1,632题，覆盖代码、企业、游戏、数学科学及对话；其中1,137题由作者设计轨迹，955题使用作者编写规则的模拟器，因此执行参考可靠与现实服务覆盖广度应分别判断。评分先用确定性检查处理能明确匹配或冲突的答案，其余交给语义裁判。20个模型中最高总通过率为49.57%；作者报告，当变化须传播到依赖对象时，跨模型平均通过率降到5.1%。这个数字描述特定题集上的预测正确率，不是完整软件复刻成功率，也不证明某个生产服务只有这一水平。

建议先读§3和图1，再看结果按历史距离与影响范围的分组，分清“读到真实历史后预测”与“维护自己生成的状态”。

## 2. EmailBench: A Benchmark for Evaluating LLM Agents on Enterprise Email and Productivity Tasks

Microsoft；Mukul Singh等8位作者；2026-09-25 v1，预印本，旧文补读。[原文](https://arxiv.org/abs/2609.31906) · [全文](https://arxiv.org/html/2609.31906v1)

邮件助理的难点常在组合操作：从邮件找参与者，确定时间，再构造含参会人与时区的日历对象。单次调用没有报错，不表示工作流满足用户要求。作者因此构建206个场景、16个类别，用统一的类型化接口和合成邮件语料评估端到端任务，而不是只判函数名和参数格式。

环境采用提供商中立的命名和确定性种子数据。论文中的文件夹任务要求先建层级，再把返回的文件夹ID传给后续路由操作。但§3.1同时明确：后端保留固定语料，把操作写入独立的类型化动作日志，后续邮件读取仍基于原语料，并非完全更新后的邮箱视图。这意味着它可以记录智能体做了什么，却不能自然代表所有“改完再查”的真实服务行为；一个要求读回验证的策略可能受这个设计影响。

作者用258条静态断言与211个场景语义评分规则联合评测；43个场景完全依靠语言模型裁判。静态断言也不全是数据库验真，123条是答案子串检查；文件夹存在本身不证明所有邮件已正确移动。两类分数都可用时各占一半，场景分数至少0.5且关键断言通过才算成功。八种记录的模型配置各跑206题一次、共享最多15轮的调用流程，最好配置场景通过率33.5%，而99.7%的调用没有观测到API失败。两个百分比分母不同：前者是场景，后者是调用；它们共同说明运行正常远不够，但不能拿差值当失败因果分解。

建议先读§3.1—3.3，再看§5.3，重点理解固定语料、动作日志和通过规则各自能证明什么。

## 3. SentinelBench: A Benchmark for Long-Running Monitoring Agents

Microsoft Research；Matheus Kunzler Maldaner、Adam Fourney等；2026-06-03首发，06-05 v2，预印本，旧文补读。[论文](https://arxiv.org/abs/2606.05342) · [全文](https://arxiv.org/html/2606.05342v2) · [官方技术介绍](https://www.microsoft.com/en-us/research/articles/sentinelbench-a-benchmark-for-long-running-monitoring-agents/)

通常的交互任务把进展看成智能体动作的结果，但监测任务中，外部世界会自己变化。反复刷新不会让新邮件更早到达；太早停止又会错过条件。作者用100个任务、10个合成网页环境，研究智能体能否等待，在条件满足后及时响应，同时控制资源消耗。

每个环境执行预先编排的事件时间线。启动时服务载入场景和用于评分的SQL；智能体访问起始页面后时间线开始，数据库随外部事件更新，页面展示相应内容。智能体通过联系表单表示完成，服务停止剩余事件，再依据数据库查询判定。任务区分只需观察与须主动打开页面获取信息，也区分绝对条件与相对初始状态的条件。另有20题条件永不触发，要求持续观察到结束，防止智能体在期限前无条件宣告成功。

作者比较三个模型和两个浏览器执行框架变体，主要差异是等待工具。sleep只暂停一段时间；wait_for先保存页面文本基线，每秒比较变化，发现未判断过的新变化才调用模型检查条件。默认任务最长10分钟。官方报告GPT-5.4条件下，两种策略的单任务中位API成本为1.17美元与0.23美元，约5.1倍，完成率相近或后者更好。这是特定模型、工具实现与合成事件安排下的比较，不是所有等待任务的固定节省比例，也不能把文本差分检测的好处全部归于模型。

建议先读任务生命周期与实验等待工具部分，再看成本图，关注哪些状态由时间推动、完成信号又如何停止时间线。

## 4. Introducing STATE-Bench: A benchmark for AI agent memory

Microsoft Open Source；Lewis Liu、Nishant Yadav；2026-05-19，官方实质技术文章，旧文补读。[原文](https://opensource.microsoft.com/blog/2026/05/19/introducing-state-bench-a-benchmark-for-ai-agent-memory/)

这篇文章把记忆评测从“能否找回过去一句话”转向“经历是否改善企业任务表现”。客服、旅行和购物流程中，记住姓名不代表会先核资格、检查政策、计算费用再执行。STATE-Bench提供450个任务，每个任务带初始数据库、用户问题和成功条件，让同一个执行循环面对多轮信息收集与状态修改。

循环中，智能体拿到对话历史，调用状态化工具；用户模拟器只在被问到时提供信息，也会根据预设性格给不完整信息或提出异议。文章说模拟器受任务规则约束，测试中引入的波动约1%，但未在此文展开分母和估计方法，因此不能据此断言用户模拟误差已排除。对修改状态的任务，评分比较最终数据库；过程与信息任务则用语言模型裁判，用户体验另按五个维度评分。

每题重复五次，除平均完成率外，pass^5表示五次全部成功的任务比例。文章用无记忆GPT-5.1建立基线，旅行任务约30%能五次全过；它说明平均成绩会掩盖不稳定性，没有在这篇介绍中证明某个记忆方案有效。这里的“状态化”指环境有持续数据库，“记忆”指智能体如何利用经验，两者不可混为同一变量。

建议先读The evaluation loop和Rigorous metrics，分清每题五次全过与五次平均通过率。

## 5. Your AI coding agent evaluation is only as good as its sandbox

Microsoft for Developers；Waldek Mastykarz；2026-09-16，官方实质技术文章，旧文补读。[原文](https://developer.microsoft.com/blog/your-ai-coding-agent-evaluation-is-only-as-good-as-its-sandbox/)

作者原本想测试模型是否已经知道特定Dev Proxy版本的行为，而不是能否现场查资料。关闭网页工具与curl后，不少新版本问题仍然答对。查看轨迹才发现：机器上的产品安装和源码检出提供了答案。因此结果正确，同时测量目标已经改变。

文中记录了绕过单条工具限制的具体路径：一次查询安装位置被阻止后，智能体改用which定位可执行文件及源码目录，再用搜索工具读取版本标签和Git历史，找到与问题相关的实现。这里不是作者报告的攻击成功率或大规模受控试验，而是有轨迹依据的工程案例。它证明这个测量现场存在信息泄漏路径，不证明所有智能体都会以同样频率利用它。

作者由此主张按可获得的信息定义边界，而不只列禁用命令。工作区外源码、缓存、安装软件、工具输出和附加服务都可能形成替代通路；检查最终答案无法还原信息从哪里来，需要连同失败调用与后续成功路径审阅。本文没有提供一套已实证覆盖所有泄漏路径的隔离方案，工程建议和案例事实应分开理解。

建议先读A correct answer can invalidate the result和Agents search the whole environment，跟清这一次案例如何通过另一条路径得到目标版本源码。
