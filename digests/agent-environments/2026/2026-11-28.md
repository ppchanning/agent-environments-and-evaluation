## How we built the agents that built AWS Emulator

[原始资料](https://www.aboutamazon.com/news/aws/how-autonomous-ai-agents-built-aws-emulator)

AWS 工程团队描述了三组代理的构建循环：在真实云服务上建立多步测试，在本地仿真器上重放，再依据差异修复。队列流程可同时核查状态码、资源和副作用。

**证据范围。** 初始 438 个接口模型描述接口范围。公开文章没有用独立保留工作流来估计未见组合的保真度。

**先读。** 对照工程文章的队列示例和 [AWS 测试准则](https://docs.aws.amazon.com/emulator/latest/userguide/fidelity.html)，辨认真实云端和本地仿真的职责。

## Spec2Repo: Benchmarking Repository Construction against Behavioral Specifications

[原始资料](https://openenvision.org/Spec2Repo/) · [全文](https://openenvision.org/Spec2Repo/Spec2Repo.pdf)

从行为规范和空目录构建可执行仓库，评测者用隐藏测试通过公开接口验收。作者报告五种语言、150 个任务、1,962 项能力及 16,597 个测试。一项任务的 69/72 测试通过仍对应 0/3 完整能力。

**证据范围。** 测试覆盖写进规范的行为。未写明规则、独立参考的状态保真和现场运行还有各自的验证要求；首个全文公开时间未核实。

**先读。** 读 §4.3 的 alertmanager 示例，核对逐测试与逐能力的分母。

## Evaluating More with Less: Black-Box Test Selection for AI Agents

[原始资料](https://arxiv.org/abs/2611.34617) · [全文](https://arxiv.org/html/2611.34617v1)

作者在十套基准的历史逐任务结果上比较两种选题目标：估算总体分数以及优先发现失败。在 SWE-bench Verified 的 500 题中选 100 题时，13 个配置上难度排序检出的失败数中位数为 53，随机法为 27.4。

**证据范围。** 困难样本的失败比例无法直接估计整体。实验重用已有基准结果，且有部分套件重叠。

## Trajectory2Gym: Decision-Grounded Compositional Interaction Synthesis for Tool-Use Agents

[原始资料](https://arxiv.org/abs/2610.33568) · [全文](https://arxiv.org/html/2610.33568v1)

从工具环境中执行并筛选交互，按可见信息和动作前提补训练轨迹。两组各使用 14,819 条交互且监督目标 token 数相同，按依赖筛选的一组多覆盖 942 种标准化路径。Tau2 三领域等权成功率由 74.17% 升至 75.83%。

**证据范围。** 作者每个对照条件只运行一次，另一基准略降。训练轨迹来自既有工具环境，覆盖和学习表现仍需与模拟器行为验证分开。

**先读。** 读附录 G.1，比较同一订单中前一步操作如何限制下一步。
