## 1. Silent Instrument Errors Reorder Agent Leaderboards

来源：[arXiv预印本](https://arxiv.org/abs/2611.04399)｜2026-11-03｜近7天补读

这篇论文问的不是哪个智能体更强，而是榜单记录的失败到底有没有被评分。山东大学的 Yangze Liu 只分析 HAL 和 τ²-bench 已公开的轨迹、评分代码与结果，不重新调用模型。它把一次评测拆回实际运行过程：谁结束会话、什么时候触发数据库比较、哪些动作由智能体执行、哪些是裁判重放参考答案时写进去的。这样才能判断一个零分代表任务失败，还是评分根本没发生。

最直接的发现来自航空客服任务。HAL 的通用智能体发出结束消息后退出，但模拟用户没有再返回终止标记，环境便不触发评分；专用工具调用框架更容易触发正常结束。作者从动作来源重建评分是否发生，发现两者评分覆盖率分别为51%与98%。将智能体实际执行过的动作放入固定环境、按原有奖励函数补算，九个模型在41个相关任务上的汇总准确率从0.30升到0.43，原先13个百分点的框架差距消失。这并不等于通用框架处处更好：只看必须写数据库的任务，修正是0.28到0.33；不少总增益来自原本只读、按既定规则保持数据库不变便可通过的任务。框架的信息位置与步数预算也仍有差别。

另外三个案例解释了为什么结果看起来合理却可能错：嵌套追踪把同一次模型响应的父子调用重复计费；参考答案的重放动作混进智能体动作列表；新版裁判重新读取旧轨迹时误识别运行模式。作者据此建议报告实际被评分比例、按根调用汇总成本、标记动作来源并发布裁判版本及重评分差异。它证明了具体公开系统中的测量故障，不给出所有榜单的故障发生率。

建议先读§3.2与表1，弄清51%评分覆盖率如何被识别，以及汇总差距和必须写库任务差距为何不同。

## 2. UserProxyBench: Evaluating LLM User Simulators for Agent Benchmarks and Training

来源：[arXiv预印本](https://arxiv.org/abs/2609.38043)｜2026-09-29｜旧文补读

在客服智能体评测中，另一个语言模型往往扮演用户。它什么时候给订单号、会不会说自己已经操作设备，都会改变智能体面对的任务。Ashish Jain 与 Armaan Sandhu 的 UserProxyBench 不问这个用户像不像真人，而问它有没有遵守任务给定的角色契约：知道什么、不知道什么、何时允许披露、必须完成哪些操作。这个区别让“仿真忠实度”有了独立于最终任务成功的定义。

方法从每道题的私有用户说明、通用规则与工具列表出发，由模型写出4—8条可被轨迹否证的判据，每条都必须有原文依据；另一个模型检查判据的依据、可实现性与范围，随后由原生成模型在不知道用户模型身份的条件下评分。一条轨迹必须满足所有适用判据才算契约通过，UFS就是这种轨迹占比。论文共构造2141条判据。比如电信用户在未被询问前就主动给出姓名和号码，会跳过本应由智能体完成的信息收集；这是论文中的实际失败类型，并非单纯的对话风格差异。

作者冻结GPT-5.5作为智能体，只替换七种用户模型，在电信、航空、零售和银行知识共375道题上各运行一次。智能体平均奖励从0.644变化到0.796；2625条计划轨迹中2618条可评分，而成功轨迹里仍有24.4%违反用户契约。提前披露尤其难被最终成功率捕获：成功轨迹中它伴随平均少1.06次工具调用。这里对失败类型的比较是观察性分组，不能把它读成随机干预得到的纯因果效应。

建议先读§2、§3.3与附录C，关注“提前泄露信息”和“声称操作但未实际写入”如何分别被发现及漏检。

局限：同一模型生成并评分判据，人工核验规模有限；探针中部分漏操作仍被判合规，语言模型评分不能直接作为状态正确性的金标准。

## 3. Tycho: Active Abstraction with Programmatic World Models for ARC-AGI-3

来源：[arXiv预印本](https://arxiv.org/abs/2607.28287)｜2026-07-30｜旧文补读

Tycho研究一个很接近黑盒重建、却目标不同的问题：智能体面对陌生的交互游戏，只有像素网格和可用动作，需要一边推断规则一边以尽量少的动作通关。Jens Lehmann、Andrei Aioanei与Sahar Vahdati让编码智能体把自己的猜测写成可执行程序，用它预测、规划，也允许智能体决定暂时不用它。研究重点因而不是强制每一步都拥有完整仿真，而是什么时候建模值得花成本。

系统把真实交互记录与模型推演分开保存。记录包括可行动帧、动画、过关与死亡等不同事件；程序需要保留隐藏状态，描述动作如何更新状态，再渲染观察和判断结局。只有执行者能改变真实环境，建模者只能编辑假设并给建议。验证用已有真实记录检查程序，规划则从程序维护的状态展开。作者还允许程序对不知道的像素弃答，或对显示量化造成的歧义给有限候选，因此“预测被接受”必须结合预测覆盖范围理解，而不是默认全屏精确重现。

作者在25个公开游戏、183个关卡上，以Opus 4.8比较不建模、自主建模、按需委托和失败后自动修复四种策略，配置相同推理预算上限，每种只有一次完整运行。按需委托取得最高平均RHAE 88.49，自动修复虽使历史转移预测更准确，RHAE却只有83.07。RHAE以人类首次游玩动作数为参照衡量动作效率，不是仿真准确率。公开集有五个游戏参与系统开发，且上限相同不代表实际推理开销相同，故这组结果支持特定系统的权衡，不能确立普遍最优的建模策略。

建议先读§4与§5.1的策略比较，重点看自动修复为何提高回放准确度却没有带来最高动作效率。

## 4. Video2World: Benchmarking Coding Agents for Interactive World Modeling from Embodied Videos

来源：[arXiv预印本](https://arxiv.org/abs/2610.04432)｜2026-10-03；v3 2026-10-09｜旧文补读

Aether AI与加州大学圣迭戈分校的Video2World把视频重建环境当成完整编码任务：输入一段人或机器人交互视频，以及目标模拟器、机器人形态和控制接口；输出既有场景，也有机器人行为的可运行程序。它不只问摆出的物体像不像，而问生成世界能否在物理执行中完成演示的交互。这使它成为环境重建评测的方法近邻，虽然领域是具身任务。

编码智能体可以查看视频和资源、修改场景参数与控制代码、运行模拟并根据反馈修正。停止后程序被冻结，评测者用不向构建者公开的物体几何、运动与任务条件检查结果。数据由189段视频形成222个重建实例，覆盖39个任务族；同一视频可以对应不同目标配置。评测分别检查能否运行、几何误差、物体运动以及关键交互是否完成，而不把渲染相似度当作功能正确的替代。

正文比较九个编码智能体系统，每实例自主构建一次，允许180分钟内迭代。系统不全共用同一编码框架，因此比较单位包括模型、框架和推理设置。构建失败在任务成功等指标中记零；连续误差只在可比较对象上计算并报告覆盖率；先在任务族内部平均，再让各任务族等权。主要证据是许多程序已能执行，却只能取得局部任务进展；对象形状重建最好的系统并不是任务完成最好的系统。作者还设置人工协助重建参考，它整体较好但也不能保证每次完成任务，所以它是经验参照，不是理论上界。

建议先读§3.2—3.3与图4，弄清几何忠实、物理可执行和任务完成分别由什么证据支持。

## 5. MultiVerse: A Trustworthy Tool-Use Benchmark for Real-World Task Delegation under Harnesses

来源：[作者原始页面](https://soheeyang.github.io/publication/yang2026multiverse/)｜2026-09（作者页仅给月份）｜旧文补读／仅摘要核验

Sohee Yang等人的作者页介绍了一个跨服务工具使用基准：在自包含沙箱里模拟35个服务、809个工具，并把用户没有一次说清需求、智能体需要追问的多轮情形纳入任务。它比较十二个模型在简单调用循环与四种终端用户框架下的表现。框架在这里是模型周围组织工具、上下文和执行流程的软件，会影响同一模型实际采取哪些动作。

作者摘要报告，最强模型与框架组合平均成功率为69.8%；多轮设置里29.5%的尝试没有向用户咨询就结束，尽管完成任务需要用户持有的信息。作者还称不同框架对不同模型有增有减，平均表现接近简单循环。由于本次只找到作者原始摘要页、页面仍写“即将发表于arXiv”，没有可核验的完整方法与实验正文，我不能补写任务总数、裁判实现或统计区间，也不能把这些百分比当作已经独立复现的结论。

建议先读作者页摘要中任务与框架比较两段，先确认研究对象，再决定是否等待全文。

证据仅为作者摘要；未提供真实与模拟服务的配对忠实度检验，完整方法、任务总数及评分实现未知。
