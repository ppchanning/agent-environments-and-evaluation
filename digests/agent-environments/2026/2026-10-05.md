# Agent Environments & Evaluation · 2026-10-05

AI 辅助整理的公开资料阅读笔记。数字与结论归属于所引作者；未独立复现实验，也不代表维护者已逐篇阅读。历史核验信息见书目。

## 1. Agent-Diff: Benchmarking LLM Agents on Enterprise API Tasks via Code Execution with State-Diff-Based Evaluation

旧文补读（配置允许的重要近邻）；arXiv预印本；Minerva University，Hubert M. Pysklo; Artem Zhuravel; Patrick D. Watson。首发2026-02-11；核验v3（2026-04-28）。[原始摘要](https://arxiv.org/abs/2602.11224)｜[已核关键正文](https://arxiv.org/html/2602.11224v3)。

**方法与作者报告的证据：** 四类企业API副本、数据库状态差分契约；9模型224任务。附录G明确描述生产API与副本同请求结构对照，以及辅助agent对非法参数等边界探测。

**证据边界：** 验证覆盖指定请求集合，结构等价不等于全部值与跨序列行为等价；作者将通知等内部副作用视为评测无关，适用范围需检验。

**先读：** §3服务建模与状态差分；附录G及I。**可检验问题：** 相同文档与探测预算下，已通过端点结构对照的副本，在未见失败→重试→读取序列上还会错多少？

## 2. Simulate to Generalize: Scaling Stateful Supervision for API-calling Agents using LLM World Models

旧文补读（配置允许的重要近邻）；arXiv预印本；Apple（原文通信邮箱及作者元数据），Seanie Lee; Sanjoy Chowdhury; Chao Jiang; Cheng-Yu Hsieh; Ting-Yao Hu; Alexander Toshev; Oncel Tuzel; Raviteja Vemulapalli。首发2026-07-18；核验v3（2026-09-22）。[原始摘要](https://arxiv.org/abs/2607.16900)｜[已核关键正文](https://arxiv.org/html/2607.16900v3)。

**方法与作者报告的证据：** 自动合成API、任务、依赖历史的模拟回复及轨迹过滤。作者用LLM judge检查1000条成功轨迹26716调用，总体96.0%通过；469个写后读调用88.7%通过。200条轨迹人工与过滤judge一致95%。

**证据边界：** 这些是规格/历史一致性与过滤一致性，不是真实服务配对保真。成功轨迹抽样和LLM judge不能证明失败操作语义；v3相对旧版变化未比较。

**先读：** §3流程；§4.4；§4.6–4.7，先看write–read子集。**可检验问题：** 在同样信息和预算下，显式状态机制相对历史上下文模拟，能否减少独立参考测得的写后读与失败副作用错误？

## 3. Mid-Harness: Scaling Actions Between Model and Harness for Terminal Agents

近7天补读；arXiv预印本；NVIDIA研究论文入口（其页面日期异常，采用arXiv日期），Minki Kang et al.。首发2026-09-30；核验v1（2026-09-30）。[原始摘要](https://arxiv.org/abs/2609.39982)｜[已核关键正文](https://arxiv.org/html/2609.39982v1)。

**方法与作者报告的证据：** 固定生成器与harness，同历史采样多个动作，执行前以listwise/pointwise/pairwise选一个。TerminalBench-Lite的TMAX-9B在强验证器下Pass@1由50.00%至68.03%；弱自验证扩宽仅小幅收益。

**证据边界：** 没有候选动作gold标签；教师一致率不是动作真值。终端环境结果不能直接迁移到服务API；8候选全pairwise需28次验证调用，成本需同预算比较。

**先读：** §2机制；§4强弱验证对照；§5与附录A局限。**可检验问题：** 真实服务与副本在同一历史下对候选排序一致吗？不一致是否导致实际失败，并能在预算匹配后仍观测到？

## 4. Echoverse: Deep, Evolving Environments for Training Computer-Use Agents at Scale

旧文补读（配置允许的重要近邻）；arXiv预印本；Microsoft Research，Yash Pandya et al.。首发2026-07-30；核验v1（2026-07-30）。[原始摘要](https://arxiv.org/abs/2607.28074)｜[已核关键正文](https://arxiv.org/html/2607.28074v1)。

**方法与作者报告的证据：** 种子编译应用、修复前后端与数据库、任务在活数据上落地；数据库差分作为写任务验证依据，仍由GPT-4.1比较。§6.2两域消融：Allrecipes浅世界训练80→75，深世界80→85；Hugging Face深世界48→65。

**证据边界：** 两域、小任务集、训练数据规模相近但非逐轨迹匹配；数据库落地不意味着判分完全无LLM。自建世界与任务共同修复不等于复现指定真实服务。

**先读：** §3.2验证；§4 factory/co-evolution；§6.2；附录C.2。**可检验问题：** 固定参考任务后，增加状态依赖深度是否提升未见组合保真？收益能否与任务难度和verifier变化分开？

同一工作合并：[微软原始论文页](https://www.microsoft.com/en-us/research/publication/echoverse-deep-evolving-environments-for-training-computer-use-agents-at-scale/)与[2026-07-30官方博客](https://www.microsoft.com/en-us/research/blog/echoverse-deep-evolving-environments-for-computer-use-agents/)，只占一个名额。数据库提供依据，但附录C.2的差分裁决仍使用模型；不能称完全机械oracle。

## 5. Verify Claims, Not Scores: Evidence-Based Verification of Modular Agents

近7天补读；arXiv预印本；原文作者；不以机构名气准入，Ali Atiah Alzahrani。首发2026-10-01；核验v1（2026-10-01）。[原始摘要](https://arxiv.org/abs/2610.01348)｜[已核关键正文](https://arxiv.org/html/2610.01348v1)。

**方法与作者报告的证据：** 在合成投资决策系统中用已知隐藏机制、oracle替换、共同随机路径和组件干预逐项检验主张；明确没有LLM。示例显示局部保真改进未检测到决策收益，部分交互结论仍未解决。

**先读：** §3设计；§4.3组件替换；§5.3；§7局限。**可检验问题：** 如果副本更准确但agent成绩不变，是测量不敏感、决策掩盖，还是仿真改进确实无用？
