## 1. Inferring data model from service interactions for response generation in service virtualization

[原始论文](https://doi.org/10.1016/j.infsof.2021.106803) · [正文入口](https://www.sciencedirect.com/science/article/pii/S0950584921002391) · 首发 未确定；期刊卷期2022-05 · 版本未确定

服务虚拟化要维持的不只是响应格式。例如先创建人员记录，再按标识查询或修改，后续结果应与此前状态相容。Hossain等研究从真实服务交互推断实体、属性和键，把数据模型与控制模型结合，用来生成响应；这是有状态服务替身的传统方法入口。

静态响应模板容易丢失实体之间的关系，活数据模型则让后续请求可以使用先前形成的数据。对仿真环境构建而言，值得比较的是哪些关系能从轨迹中推断、控制流程如何约束可用操作，以及未观察过的交互怎样处理，而非只比较单条响应文本。

资料核验范围仅为原始摘要、引言及部分章节摘录，接受稿访问受限，完整实验表未核实，因此不报告数值准确率。2022年5月为期刊卷期，首次在线日期仍不明确；不能由DOI中的年份推定首发日。

**证据范围：** 仅原始摘要、引言和部分章节摘录。

**先读：** 第2节人员信息例子、第3节模型构造；第4节原实验表待核。

## 2. GTDD: Generative Test-Driven Development for AI Coding Agents with Adversarial Testing

[原始论文](https://arxiv.org/abs/2610.02952) · [正文入口](https://arxiv.org/html/2610.02952v1) · 首发 2026-10-02 · v1

GTDD把生成测试与候选程序开发联系起来，利用固定参考行为上的差分轨迹检查多步错误。对有状态模拟器而言，一次调用通过测试不保证十几步之后仍维持相同状态，这使保留动作序列及参考输出成为重要验证方式。

论文报告30个配对块，并在2000条、每条10至40步的保留轨迹上审计：动态知情测试的轨迹失败率27.4%，静态测试40.5%，属性测试29.8%。动态方案相对属性测试没有显著优势，测试预算的差异也尚未排除，因此不能把较低数字全部归因于某一种生成策略。

开发阶段并未实际把独立审计作为接受门槛。文中的新样本保证受有限总体与抽样条件约束，不能解释为所有动作序列正确。它提供的是软件行为验证方法，不是已经证明任意服务仿真保真的环境。

**证据范围：** 原始元数据及相关正文方法与结果；未独立复现。

**先读：** 第6.1–6.3节、表5/6、独立审计抽样条件。

## 3. MCP-Universe: Benchmarking Large Language Models with Real-World Model Context Protocol Servers

[原始论文](https://arxiv.org/abs/2508.14704) · [正文入口](https://arxiv.org/html/2508.14704v1) · 首发 2025-08-20 · v1

MCP-Universe评测代理调用真实MCP服务完成任务，而不是用语言模型假装后端。其价值在于把自然语言请求与可执行验收器分开，让“工具调用成功”和“任务完成”能够分别核查；这些验收方法可作为仿真与真实服务比较的参考。

论文版本包含231项任务、6个领域、11个服务器、133个工具和84种不同评价器。历史GPT-5任务成功为101/231，即43.72%，平均评价器满足度为60.23%；两者分母和含义不同，不能互换。任务刻意选择较难的案例，不代表真实用户请求的自然分布。

动态外部服务与数据会影响重复执行的结果，比较仿真时需要固定版本与参考条件。这些是论文版本的结果，不是当前排行榜；官方博客与论文视作同一工作，仓库持续变化本身不构成本次已核实的新版本。

**证据范围：** 原始元数据及相关正文方法与结果；未独立复现。

**先读：** 第3.4节和表2/3。

## 4. Which Metadata Matters for LLM Tool Selection in MCP? Evidence from Controlled Factor-Level Interventions

[原始论文](https://arxiv.org/abs/2610.14334) · [正文入口](https://arxiv.org/html/2610.14334v1) · 首发 2026-10-09 · v1

这项MCP研究问工具名称、说明、schema及位置会怎样影响模型首次选择工具。它先整理367174项工具元数据，再在5项任务和5个模型上做受控因素干预，将接口呈现方式与工具选择相联系。

PlaceOrder双工具条件中，GPT-5.4 mini在平铺schema下选择率97%，但当位置变化时可见首位偏好51%的表现。这些是指定实验条件下的选择统计，不能解释成97%的订单执行成功率；研究没有执行工具来核验副作用或最终状态。

仿真验证若同时改变工具元数据、名称或排序，观察到的差异可能先来自代理选择，而非后端状态模型。该论文因此提供接口控制的支撑方法，尚未测量服务仿真保真度。10月9日首发为较早工作此次补入书目，并非今日新发。

**证据范围：** 原始元数据及相关正文方法与结果；未独立复现。

**先读：** 第4节、第5.2节位置效应、第5.4节明确请求条件。

## 5. Sim2Real Predictivity: Does Evaluation in Simulation Predict Real-World Performance?

[原始论文](https://arxiv.org/abs/1912.06321) · [正文入口](https://arxiv.org/pdf/1912.06321) · 首发 2019-12-13 · v2, 2020-08-17; RA-L2020

Sim2Real Predictivity考察模拟器中的代理成绩能否预测真实机器人导航表现。只让渲染画面看起来合理还不够：若不同策略在仿真与真实场景中的排名翻转，模拟评测就可能误导模型选择。该问题与软件服务模拟的外推效度相关，但实验对象是机器人导航。

作者在每一侧运行9种模型、3个配置、5对起终点和3次重复，共405次。调整模拟器后，成功率的SRCC由0.18升至0.844，SPL由0.603升至0.875。这里是模拟与真实性能的相关性指标，不是84.4%的任务成功率或状态准确率。

调整与评价使用同一实验室及模型集合，尚不能视为对未见环境的独立外推验证。阅读应关注调整机制、排名变化和参考条件；它提供验证仿真用途的思路，而非对API服务或任意代理系统的直接保证。

**证据范围：** 原始元数据及相关正文方法与结果；未独立复现。

**先读：** 第IV-E节及第V-A/V-B节图5–7。
