# 仿真环境与可信验收｜2026-10-22

AI辅助资料整理；本期5项首次进入本集合，保留来源原始日期，不表示当日新发表。推荐不代表维护者已读；数字为作者报告，未独立复现实验。真实执行、训练环境改造、工具仿真和工程经验分别说明。

## 1. Doc2Harness: Benchmarking LLMs on Long-Horizon Harness Engineering of Coding Agents

Yuyao Ge et al.。preprint，来源首发日期：2026-10-14；版本：v1。[原始来源](https://arxiv.org/abs/2610.20344) · [正文](https://arxiv.org/html/2610.20344v1)

Doc2Harness要求模型依据去冲突的框架文档规格和骨架，构建完整编码智能体运行框架。规格来自12个框架，并非发现或复现一个现成目标服务。每次在隔离容器中最多构建两小时、提交三次；安装、接口及非空检查通过后冻结产物，在全新容器中执行隐藏行为测试。

测试用脚本化假模型响应驱动运行时，再观察请求、文件和退出码，避免只用语言模型评价“看起来正确”。328项测试中130项有合法行为对照：例如拒绝越出工作目录的符号链接，只有同时能够读取目录内合法链接才算真正遵守边界，不能靠全部拒绝取巧。

19种模型各构建三次，最佳平均通过率53.05%，分母为328项主测试，合法对照不另加进分母。该结果衡量给定规格下的框架构建，不是对所有既有框架质量的普遍排名。对仿真验证而言，成对正反行为控制提供了可借鉴的验收方法，但本文不声称完成黑盒服务重建。

**证据限制：**完整规格合成不同于未知服务重建；合法对照不额外计入328项分母。

**建议先读：**第2.4节、图2

## 2. TRACE: Diagnosing Verifier Brittleness in Agentic Evaluation

Radhika Gaonkar。preprint，来源首发日期：2026-10-08；版本：v1。[原始来源](https://arxiv.org/abs/2610.11678) · [正文](https://arxiv.org/html/2610.11678v1)

评测成绩下降，可能是代理真的做错，也可能只是验收器没认出正确结果。TRACE区分策略、环境和评分器变化：冻结轨迹重新评分，能够隔离评分器问题；让代理重新执行，则又混入行为改变和运行随机性。

25项合成任务提供已知原因的干预，例如工具名不匹配造成分数下降0.250，规范化后重评分恢复。扩大到88项新的公开τ²航空与零售任务、每条件三次运行时，四种代理和两种保义变换的八组比较中，七组置信区间落在±0.10等效界内，不能再把小样本现象写成稳定的大幅损失。

误导性名称这一正对照仍造成0.20至0.44下降，而重复执行中的逐任务结果翻转为15%至36%。等效区间也不意味着逐任务完全一致。模拟器与真实服务比较若只看一次总分，便难分清状态保真、评分偏差与随机性；本文提供的是诊断方法，不是所有表示变化必然有害的证明。

**证据限制：**扩大实验并未支持普遍显著下降；等效界不等于完全相同；重跑存在较大逐任务波动。

**建议先读：**第3.1节、第5节

## 3. TRAP: Tool-result Replay Attack for Probing Misbinding in LLM Agents

Yutong Zhi, Jie Zhang, Xiuqi Lu, Jiayuan Xu, Jing Shao。preprint，来源首发日期：2026-10-12；版本：v1。[原始来源](https://arxiv.org/abs/2610.16333) · [正文](https://arxiv.org/html/2610.16333v1)

TRAP将真实工具返回重放到错误上下文，检验代理是否把旧结果、旧授权或错序输出绑定到当前任务。它不靠在返回中插入恶意指令，而以19类场景模拟缓存、队列和持久状态中的上下文错配；这是受控注入测试，不是确认现有平台已有漏洞。

评估区分三个阶段：错误结果送达、模型提出错误动作、运行时接受动作；最终另查持久状态。八种模型、三个框架、七种代表场景共168组配置，通常每组十个有效试验，最终状态错误率均值0.649。该值以已注入有效试验为条件，不能解释为自然使用中64.9%的故障发生率。

重新验证动作前提在测量配置中消除了错误，但还应检查合法恢复动作没有被一并拒绝。对于服务仿真，参考服务真实的过期、重复和顺序语义是对照依据；不能为了让代理更安全而悄悄把模拟器改成另一套理想策略。

**证据限制：**受控注入条件概率并非自然故障率；忠实仿真以参考服务语义为准。

**建议先读：**第3.3节、附录E

## 4. EnvHarness: Awakening Static Worlds for Agent Learning

Chengsong Huang et al.。preprint，来源首发日期：2026-08-20；版本：v1。[原始来源](https://arxiv.org/abs/2608.19880) · [正文](https://arxiv.org/html/2608.19880v1)

EnvHarness主动改变训练环境，使代理获得更多交互经验。它围绕reset/step接口，从Stage初态、Contract规则及Chain长任务组织变化；附录使用Setup/Rule/Link名称。与忠实重建固定服务不同，这里的环境改变是设计目标，应分别判断训练效用和行为保真。

EnvRigger先用五条原环境轨迹诊断，再为候选生成五条轨迹，最多五轮接受、拒绝或修改。主自动化结果排除了Chain，因为隐藏内部状态使自动处理更困难，不能把三类全部算作已验证主流程。作者从生成环境提取检索技能，回到未改动的留出环境评测，并控制种子、环境数、提取方法及模型，不引入更强外部教师。

ALFWorld分布外准确率从61.4%到70.4%，增加9个百分点；另一项非重叠Lite训练后的SWE407 Verified评测，平均步数由55.01到49.61，约少9.8%。两个数来自不同任务，不应合成同一系统同时更准更快的结论，生成过程另耗轨迹。参见[作者代码](https://github.com/google-research/envharness)。

**证据限制：**主自动流程排除Chain；两个基准指标不可合并；环境生成额外消耗交互。

**建议先读：**第2.2节、第4.1节

## 5. How to test agent skills without hitting real APIs

Waldek Mastykarz。official_technical_article，来源首发日期：2026-07-17；版本：网页。[原始来源](https://developer.microsoft.com/blog/how-to-test-agent-skills-without-hitting-real-apis/) · [正文](https://developer.microsoft.com/blog/how-to-test-agent-skills-without-hitting-real-apis/)

这篇Microsoft官方工程文章介绍用Dev Proxy拦截原API地址，测试智能体Skill时减少真实调用。无需把地址改成localhost，但文章没有测量地址外观是否影响模型行为，不能把该便利性扩展为已验证的行为收益。

配置用JSON建立可重置初始数据，支持getAll、getOne、merge和delete。写入后再次读取会反映变化，因此它比永远返回同一JSON的固定mock多了一层有状态行为，可作为简单CRUD工具服务的测试替身。

文章没有给出与真实后端的差分验证，也未覆盖完整业务约束、事务与并发语义。50场景、三个模型、五次重复共750次调用只是成本算例，不是已完成实验。阅读时可先看“A lighter-weight approach”，再判断具体服务还需要哪些状态及异常控制。

**证据限制：**官方技术文章而非受控实验；无真实后端差分验证；750次调用为假设算例。

**建议先读：**A lighter-weight approach
